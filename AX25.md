# Estivi AX.25

A client reads two kinds of UI frame. Both are addressed to `ESTIVI`. The info field is UTF-8 text. Ignore every other transmission.

The text format version is the `1` in `ESTIVI 1`. It is not the `.estivi` file version.

## Where the frames sit

On a grid transmission the same info frame is sent twice: once before the pictures and once after the last picture. A transmission cut at the end of the block may lose the second copy. The two copies are the same text.

Each SSTV piece can be announced by its own short mode frame, placed immediately before that piece. The piece is then a VIS header and the picture. The marks are:

| Piece | Example |
|---|---|
| The picture | `ESTIVI MODE M1` |
| Welcome, first turn of a program block only | `ESTIVI MODE R36 WELCOME` |
| A pre-bumper | `ESTIVI MODE R12 BUMPER PRE` |
| A post-bumper | `ESTIVI MODE BW8 BUMPER POST` |
| Bye, last turn of a program block only | `ESTIVI MODE R24 BYE` |

The short code is whatever mode that piece uses. A turn that is both first and last carries the welcome and the bye. Either kind of frame can be switched off at the channel, so a client must accept a picture with no mode frame and a mode frame with no info frame.

An activation can send an info frame with a subset of the lines, plus a `COMMENT` line. A command or API answer sent as AX.25 is the raw answer in the info field and does not follow this text format. Treat an info field that does not start with `ESTIVI ` as opaque text.

## The bytes on the air

1200 baud AFSK, Bell 202. Mark is 1200 Hz, space is 2200 Hz. The bit is 1000/1200 ms. NRZI: a zero flips the tone, a one holds it. The tone starts as mark, before the first bit. Bits are sent least significant bit first. After five ones in the body, a zero is stuffed. Flags are `0x7E` and are not stuffed.

The audio is 24 flags, the frame, three flags, then 100 ms of silence.

The frame, before stuffing:

| Field | Value |
|---|---|
| Destination | `ESTIVI`, SSID 0, command bit set, not the last address |
| Source | The station callsign, SSID from a `-N` suffix |
| Control | `0x03` (UI) |
| PID | `0xF0` (no layer 3) |
| Info | The text, including its final `\n` |
| FCS | CRC-16/CCITT reflected, init `0xFFFF`, xorout `0xFFFF`, low byte first |

A good frame, FCS included, leaves residue `0xF0B8`.

### Control

One byte, `0x03`. That is a UI frame: unnumbered information, with the poll bit clear. Estivi sends the text and moves on. There is no connection and no sequence number to track. A client keeps the frame when this byte is `0x03`.

### PID

One byte, `0xF0`, present because a UI frame names the protocol of its info. `0xF0` means no layer-3 protocol. The bytes that follow are the Estivi text, decoded as UTF-8. A client keeps the frame when this byte is `0xF0`.

### FCS

Two bytes after the text. They are a CRC of every unstuffed byte before them: both addresses, the control byte, the PID, and the info. Flags and the stuffed zeros are outside the CRC.

The polynomial is CRC-16/CCITT, `x^16 + x^12 + x^5 + 1`. In code that walks each byte from the low bit, the polynomial constant is `0x8408`. Start at `0xFFFF`. For each byte, XOR it in, then eight times: if the low bit is 1, shift right and XOR `0x8408`, otherwise shift right. The value on the air is the bitwise complement of that result, low byte first.

Checking a received frame is the same walk over the addresses, control, PID, info, and the two FCS bytes. The frame is intact when the register ends at `0xF0B8`. Any other residue means the text is damaged, and the client drops the frame.

The source callsign is at most six ASCII letters or digits, upper case. A trailing `-N` with `N` from 0 to 15 is the SSID. Anything else in the callsign is dropped. An empty callsign is sent as `NOCALL`. The `CALL` line in the text is the callsign as configured, and can be longer than the address.

## Info frame

Lines end in `\n` (`LF`). The frame ends with `\n`. A line that does not apply is omitted, not sent empty. Unknown lines are ignored. The keywords that are present always come in this order:

```
ESTIVI 1
FREQ 145825000
CALL LU1ABC
NAME Noticias
RANGE 14:00-14:30
DAYS Mon,Tue,Wed,Thu,Fri
DAYSLEFT 12
NEXT Noticias|14:00-14:30|Mon,Tue,Wed,Thu,Fri|12
NEXT Clima|18:00-18:15|Sat,Sun|0
COMMENT hola mundo
```

`COMMENT` is only sent by an activation, and only when the comment is not blank.

A newline or a `|` inside a name, a callsign, a range, or a comment is replaced with a space. The text is one physical line per field.

### `FREQ`

Integer hertz. `0` means the channel is not retuning the radio. It is not megahertz.

### `CALL`

The station callsign, one line.

### `NAME`

The block name. A program block sends the program name. A common block with no name sends `Block`.

An activation sends the activation name. Its `RANGE` line is blank (`RANGE `), and it has no `DAYS`, `DAYSLEFT`, or `NEXT`.

### `RANGE`

`HH:MM-HH:MM`, the block's own clock, 24 hour, zero padded. The frame does not say whether that clock is UTC or local, and it does not carry the date. If the end is earlier than the start, the block crosses midnight.

### `DAYS`

Present only for a program block. English abbreviations, Monday first, comma separated, no spaces: `Mon,Tue,Wed,Thu,Fri,Sat,Sun`. Only the days that are on are listed. A common block omits the line.

### `DAYSLEFT`

Present only for a program block that has not expired.

| Value | Meaning |
|---|---|
| `0` | No end date, or more than 99 days left |
| `1` | Today is the last day |
| `2`…`99` | Days left, counting today |

A common block omits the line. An expired program is not announced as the current block.

### `NEXT`

One line per upcoming block, soonest first. The current block is not included. The four fields are separated by `|`:

```
name|HH:MM-HH:MM|days|daysleft
```

`days` uses the same names as `DAYS`. A common block has an empty `days` field and `daysleft` `0`:

```
NEXT Noche en 80 m|21:00-23:30||0
```

`daysleft` here is `0` for a common block, for a program with no end (or more than 99 days), and for an expired program. It is never omitted inside a `NEXT` line.

How many lines appear is up to the sender: either a count (the default is 8) or every block that starts within a number of hours (the default horizon is 6). The sender may also keep only the next block of each other program and drop further blocks of the program that is on the air. A client displays the lines it received.

## Mode frame

One line, with the final `\n`:

```
ESTIVI MODE <short>
ESTIVI MODE <short> <mark>
ESTIVI MODE YQ <stamp>
ESTIVI MODE YQ <mark> <stamp>
```

`<mark>`, when present, is exactly one of `WELCOME`, `BUMPER PRE`, `BUMPER POST`, `BYE`. Without a mark, the frame belongs to the main picture.

`<stamp>` is fourteen digits, `ddmmyyyyhhnnss`, and only a YoniQ frame sends it. It is the local time used to name the clean BMP. It is not part of the picture. A receiver that does not know the token ignores it.

`<short>` is one of:

| Short | Mode | Picture | Lines | VIS |
|---|---|---|---|---|
| `M1` | Martin M1 | 320×256 | 256 | `0x2C` |
| `M2` | Martin M2 | 320×256 | 256 | `0x28` |
| `M3` | Martin M3 | 320×256 | 128 | `0x24` |
| `M4` | Martin M4 | 320×256 | 128 | `0x20` |
| `S1` | Scottie S1 | 320×256 | 256 | `0x3C` |
| `S2` | Scottie S2 | 320×256 | 256 | `0x38` |
| `SDX` | Scottie DX | 320×256 | 256 | `0x4C` |
| `R24` | Robot 24 | 160×120 | 120 | `0x04` |
| `R36` | Robot 36 | 320×240 | 240 | `0x08` |
| `R72` | Robot 72 | 320×240 | 240 | `0x0C` |
| `R12` | Robot 12 color | 160×120 | 120 | `0x00` |
| `BW8` | Robot 8 black and white | 160×120 | 120 | `0x02` |
| `BW12` | Robot 12 black and white | 160×120 | 120 | `0x06` |
| `BW24` | Robot 24 black and white | 320×240 | 240 | `0x0A` |
| `PD50` | PD 50 | 320×256 | 128 | `0x5D` |
| `PD90` | PD 90 | 320×256 | 128 | `0x63` |
| `PD120` | PD 120 | 640×496 | 248 | `0x5F` |
| `PD160` | PD 160 | 512×400 | 200 | `0x62` |
| `PD180` | PD 180 | 640×496 | 248 | `0x60` |
| `PD240` | PD 240 | 640×496 | 248 | `0x61` |
| `PD290` | PD 290 | 800×616 | 308 | `0x5E` |
| `YQ` | YoniQ | 320×256 | 128 | `0x73` |

Picture is the image size. Lines is how many go on the air. YoniQ sends 128 line pairs (Y of the even row, R-Y and B-Y of that same row, Y of the odd row).

Match `<short>` case-insensitively. An unknown short code still labels the following picture; the VIS that follows is the authority for a decoder.

YoniQ is the only mode whose VIS parity bit is odd. The eight bits on the air, least significant bit first, are `0x73` (parity bit 0). Every other code in this table uses even parity.
